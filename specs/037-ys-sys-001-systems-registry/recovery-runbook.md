### Restore role and privilege prerequisites

The failed first attempt shows that an isolated PostgreSQL target does not automatically contain Neon-managed global roles referenced by a full database archive. A database dump does not create cluster-global roles. Before another restore, privately inventory the archive's owner/ACL/role dependencies and the target provider's supported role model. Confirm the restore operator has only the target-scoped authority needed to create the disposable database and restore its objects, plus the necessary ownership/role mapping and extension prerequisites. Validate whether the archive can be restored using provider-supported roles or a reviewed role mapping without changing intended ownership or security behavior.

For a future restore, the required capabilities depend on the exact approved restore command and archive metadata; confirm them before execution rather than granting a blanket role. A restore operator using `pg_restore --create` needs permission to create the target database; without `--create`, the target must already exist and the operator needs connect/create rights there. Object creation and ownership restoration require suitable target-schema authority and either the referenced owner roles or explicit membership/role mapping approved for that isolated target. Restoring ACLs requires the relevant grant authority. Required extensions must be available on the target and installed with provider-supported privileges. Provision global roles and memberships separately from the database archive and least-privilege the operator to only the disposable target. If faithful ownership, grants, RLS, and extension behavior cannot be restored without superuser or broad cluster administration, stop and obtain a reviewed provider-compatible procedure; do not weaken the archived security model silently.

Never emulate `neon_superuser`, create a role with superuser or other elevated provider privileges, or grant broad privileges to make restoration pass. If an archive dependency cannot be satisfied by the isolated target's supported roles, stop and obtain a provider-compatible restore method or a reviewed, least-privilege archive/restore plan. Do not suppress ownership or ACLs as a silent workaround; any owner/ACL remapping must be explicit, reviewed, and checked for grants, RLS, and object ownership after restore. Record actual required role attributes, memberships, object owners, grants, extensions, and database settings privately. No Production role or permission change is authorized.
