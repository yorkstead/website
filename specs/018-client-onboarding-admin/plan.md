# Architecture and audit

CC-002: customer_tenants, customer_tenant_projects (globally unique project mapping), customer_identities, customer_tenant_memberships, customer_project_grants are authoritative. Membership roles member/admin and grant permission view are unchanged. CC-003 separates customer_auth sessions and subject mapping. Authorization joins every active lifecycle on each request; revocation denies future reads even with an existing session, so session deletion is unnecessary for scoped revocation. In-flight reads are not recalled.

CC-006 migration 0012 and createClientOnboardingService own issue/revoke/redeem. Issue creates an ephemeral raw token and supersedes prior invitations; it is deliberately NOT called from the administrative service. Its inspect query is unbounded, so the adapter uses explicit safe-column paginated queries. Invitation revoke reuses the same tenant-first lock, provisioning actor context and database guard/audit, adding CAS. CC-007 email proof and production gates remain unchanged. CC-008 migration 0014 owns publication and invalidation; CC-009 remains the publishing UI. Readiness checks current approved overview digest without disclosing workspace JSON.

No reviewed organization/mapping admin or grant/membership revocation service exists. Add trusted operations and additive migration 0015: revisions on existing records; separate preparation configuration, never a second invitation service; append-only administrative audit. New tenants/mappings start disabled and cannot be activated through this milestone. Mapping may only move toward archived; no reassignment or reactivation. No implicit grants. Unsupported identity suspension remains unavailable. Existing lifecycle schemas remain authoritative.

Production runtime hard-denies mutations. Disposable mode requires nonproduction, explicit switch, identical TEST_DATABASE_URL/DATABASE_URL, loopback PostgreSQL and test/disposable database name. Owner verification is repeated within each service method. Database transactions, tenant-first locks, CAS and existing composite constraints protect consistency. Administrative audit uses trigger-generated actor/time and contains identifiers/status/revision only, never credentials or recipient addresses. Read-only inspection uses a repeatable-read snapshot, explicit projections, per-collection pagination and bounded response size.

Prepared configuration is a retained review record only. Issued means a CC-006 row exists; delivered is unknown/unavailable (no authoritative delivery integration); redeemed is authoritative status, never inferred. Prepared expiry duration is not an actual invitation expiration.

Disposable URL validation rejects all query parameters and fragments: pg connection-string options can override host/database/port independently of the URL hostname/path. Plain loopback URLs only; no connection options are necessary in this synthetic workflow.
