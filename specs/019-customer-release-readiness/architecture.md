# Architecture and release-dependency matrix

| Authority | Implemented safeguard | Remaining qualification / owner decision |
| --- | --- | --- |
| CC-002/002A, 0009 | Active identity/tenant/membership/mapping/view-grant joins, composite tenant integrity and global project ownership | Exact-release isolation tests, least-privilege production role, separate per-customer authorization |
| CC-003, 0010 | Independent Better Auth schema, secret, cookie/base path; verified subject and per-request sessions | Production secret validity/separation, TLS/cookie/provider operational inspection unavailable |
| CC-004/005, 0011 | Owner-only previews, version-bound document audit; document capabilities false | Documents excluded with explicit justification; no document activation |
| CC-006, 0012 | Expiring opaque invitations, verifier-only persistence, immutable scope, revoke/supersede/redeem audit; no resurrection | Issuance/delivery semantics, secure transport and support review; never issue from readiness |
| CC-007, 0013 | Independent email proof, actual sessions, distributed rate limits, generic errors, same-origin/bounded JSON and negative routes | Sender/SPF/DKIM/DMARC/provider/bounces/recovery/capacity qualification; live adapters unavailable |
| CC-008, 0014 | Safe explicit publication snapshots, digest invalidation and per-request disclosure authorization | Per-customer approved overview/source review, production cache/disclosure qualification |
| CC-009 | Owner publishing/review/withdrawal and safe preview | Retained unchanged; no implicit publication from readiness |
| CC-010, 0015 | Owner access inspection, immutable preparation, CAS revocation and admin audit | Production writes remain disabled; no real customer eligibility implied |
| CC-011, 0016 | Versioned assessment, immutable evidence and generated decision audit | Separate technical/security/email/recovery/customer review and explicit future release authorization |

Hard gates remain unchanged: customerPortalCapabilities (login/invitations/publishedUpdates/documentSharing) all false; clientProjectCapabilities.customerRead false; document capabilities customerRead/customerApproval/upload/download/publish false; customerEnrollmentEnabled rejects production, including proxy/page/enrollment handlers; public Better Auth signup disabled and user-create hook false; unavailableEnrollmentDelivery throws; Client Access production mutations denied. New readiness model adds no activation mechanism.

Use existing getOwnerSession/DocumentOwnerVerifier, pg transaction/actor/append-only trigger conventions, bounded request reader and DialogBoundary. Existing tenant/document audits require customer scope and cannot safely host a global release review, so additive 0016 stores a narrowly scoped global registry and generated audit, without inventing another authorization or tenant model.

A trusted inspector produces sanitized context and allowlisted technical observations. Runtime inspects code boundaries and, only under explicit disposable configuration, migration checksum state. It does not connect to email/DNS/monitoring or inspect production secrets/customer records. Missing metadata/production adapters remain not_verified or blocked. Schema identity is the checked-in digest of all 16 historical migration checksums; schema verification compares actual migration ledger to that exact manifest. Code revision and opaque configuration identity are validated metadata only, not proof of deployed configuration validity. Production secrets, transport, release testing and operational evidence remain independent mandatory requirements.

Assessment is a pure deterministic function of context, current server observations, immutable evidence, decision and injected server clock. Technical evidence must be recorded by server verification, match the current observation fingerprint/context, and be fresh. Manual evidence is visibly an owner attestation. All mandatory global requirements must pass for approval; N/A is accepted only for the optional excluded document capability with fixed justification. Customer requirements remain separate and unresolved. Disabled routes are a safety safeguard, never evidence of readiness for a real pilot.

Transactions serialize by release-context advisory lock then review row; CAS protects revision and assessment digest. Evidence creation advances revision and invalidates current decisions; decision audit retains history. Approval binds exact assessment digest and earliest required evidence expiration. Reads recompute live observation matching and time validity; changed facts, commit, schema, configuration, missing/expired evidence or changed context make prior approval stale. No approval value is consumed by customer auth, invitations, publication, gates or grants. No customer table is queried.

Only nonsecret hashes/enums/timestamps are persisted. Registry writes use an explicit PORTAL_READINESS_DISPOSABLE switch through the reviewed CC-010 plain-loopback gate (including rejection of pg query/fragment routing overrides). Production is readonly regardless of environment flags. Metadata may be unavailable; fail closed, never fabricate a release identity.
