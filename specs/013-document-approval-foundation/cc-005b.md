# CC-005B — Production build hotfix

## Incident and evidence

Base: latest main `7a8184ca58d83d31f821b8beed5ed14cc3a79e29` (merged PR #55).
Production `dpl_3iKVpzpTPHzh3jEyvYMEb6Jztdot`: ERROR / BUILD_UTILS_SPAWN_1, `bun run vercel-build` exited 1.
PR preview `dpl_7E4HsUYQstnokJZDLzv7gq7xefdB`, commit `fb51814`: READY.

The user supplied the exact production build-log excerpt after the connected events endpoint returned 404 with confirmed team scope and the CLI fallback reported no credentials. Relevant verbatim lines:

```text
21:21:12.861 Applying ordered production database migrations before the Vercel build.
21:21:13.586 Skipping 0010 customer-authentication (already applied).
21:21:13.763 NeonDbError: cannot insert multiple commands into a prepared statement
21:21:13.764        code: "42601"
21:21:13.765 error: script "db:migrate" exited with code 1
21:21:13.767 error: script "vercel-build" exited with code 1
```

The wrapper stopped before Next.js build. The logs identify Neon's prepared-query path and rule out an application compilation error. The error is inside the transaction for unapplied 0011; the runner records its checksum only after all migration statements succeed. No production database was inspected or modified during diagnosis.

Locally reproduced defect: migration 0011 contains a breakpoint block of fourteen single-line CREATE TRIGGER commands. `pg` simple-query execution accepts that block; a named prepared query rejects it with SQLSTATE 42601, `cannot insert multiple commands into a prepared statement`. Production defaults to Neon HTTP, which prepares each execution item; CI explicitly chooses `pg` and previously used simple queries. Preview skips migrations altogether (`VERCEL_ENV !== production`), so passing preview does not test this path.

## Scope and plan

Preserve all migration file bytes/checksums and the fail-closed production migration-before-build order. Expand only blocks consisting entirely of single-line CREATE TRIGGER commands into individual execution items in the shared migration parser. Leave function bodies, dollar-quoted SQL and other statements intact. This avoids rewriting a versioned migration already applied in disposable/developer environments and introduces no schema changes, new migration or dependency.

Add parser regression tests for the grouped block and checksum stability; add disposable PostgreSQL tests reproducing the prepared-protocol failure then applying all parsed migrations through named prepared queries and confirming 0011 creates every trigger. Existing repeatability/data-preservation tests remain required. Run scaffold, migration validation, full unit/integration suite, lint, typecheck and production build. Browser behavior is unchanged; PR CI still runs the full browser matrix.
