# Threat model

Untrusted inputs: recipients, request headers/bodies, tokens, webhook payloads and provider errors. Trusted: owner session verifier, authoritative DB services, injected keyring/clock/transport in isolated tests. Environment switches never activate production.

Risks/controls: cross-tenant references (composite references and scoped joins); stolen queue DB (no plaintext token; separate authenticated encrypted custody and keyring); malicious template fields (fixed copy, strict address/token/origin validation and HTML escaping); enumeration (generic begin/finish failures and hashed account/network buckets); challenge replay/concurrency (row locks, atomic consumption and credential/session update); suspended identity/tenant or revoked invite (lock and recheck at dispatch/completion); worker race/crash (SKIP LOCKED, timeout shorter than lease, CAS fencing, fixed idempotency); provider acceptance ambiguity (bounded retries and distinct delivery fact); fake webhooks (SDK verification, signed timestamp window, durable deduplication); reordered events (monotonic terminal precedence); logging leakage (enum/code/ID-only audit, no provider response/error serialization); owner UI leakage (explicit metadata projection, no links/bodies/addresses/verifiers); production activation (hardcoded false live capabilities, no dispatcher route, nonproduction disposable writers).

Residual launch blockers: real sender ownership/SPF/DKIM/DMARC, API-key scope and secret rotation, webhook current/previous secret rotation overlap and retirement, exact-production rate-limit/queue capacity/alerts, custody key lifecycle and least-privilege DB roles, Better Auth session/cache qualification, lost-mailbox assisted verification, live independently authorized delivery and bounce/recovery rehearsal. No account recovery for missing password credentials. No automatic granting or membership repair. Do not log raw payloads even where generic provider guidance suggests it.

## Security review findings

- High, addressed, platform owner: readiness evidence could be selected by text-cast ID order across digit boundaries. Numeric source-column ordering and an isolated 99→100 regression now protect current evidence; audit ordering uses numeric IDs too.
- High, unresolved launch blocker, security/auth operator: disposable password recovery is a trusted rehearsal, not production qualification of provider-native reset hooks. Concurrent in-flight sign-in/session creation, cookie caches, external session stores and lost-mailbox support must be reviewed and tested against the exact Better Auth production configuration before any recovery controller/transport is activated. Existing session rows are invalidated atomically, but this milestone does not claim to recall an in-flight authentication request.
- High, unresolved launch blocker, platform operator: custody role/key rotation, sender/DNS/provider and exact-environment signed event delivery require separate authorized configuration and independent evidence. Code presence cannot qualify them.
- No unresolved finding authorizes production activation; hard-coded gates, unavailable customer delivery/runtime and read-only owner UI remain the controlling boundary.
