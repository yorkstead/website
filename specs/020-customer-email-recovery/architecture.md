# Architecture and existing lifecycle audit

CC-002/002a own active tenant/project/identity/membership/grant authorization, joined per request. CC-003 customer Better Auth has separate customer_auth schema, cookie and API, credential passwords (12–128 chars), verified email required, signup disabled and session creation blocked for suspended identities. CC-004 shell and CC-005 document gates remain disabled. CC-006 createClientOnboardingService owns tenant-first issue/supersede/revoke/redeem and trigger-generated audit. Raw invitation tokens are ephemeral; only SHA-256 verifiers persist. CC-007 createCustomerEnrollmentService creates a separate recipient/invitation-bound proof with 599-second expiry; completion consumes it atomically, hashes with Better Auth and creates credentials without redeeming/granting access. CC-008/009 disclosure remains separately approved. CC-010 prepared configurations are not issued invitations; production admin remains read-only. CC-011 stores immutable release context/evidence with digest/revision concurrency and same-status observation invalidation.

Optional transaction hooks on CC-006/007 append immutable delivery intent and encrypted custody inside the authoritative transaction; default constructors do not send or enqueue. Hook failure rolls back issuance/challenge. Invitation hook never delivers independent proof in the invitation email. Trusted constructors require reviewed disposable gating; production does not construct writers/workers.

Queue intent stores identifiers, exact normalized recipient/sender, fixed type/template, authoritative resource reference, expiry and deduplication key. Restricted custody holds AES-256-GCM ciphertext, random nonce/tag, authenticated job ID, opaque key version, bounded expiry. A trusted in-memory keyring is injected; no production key discovery or fallback. Missing/retired keys cancel delivery. Custody is deleted on terminal dispatch. Encrypting tokens limits database-only disclosure; application/key compromise remains in threat model. No plaintext durable secret or HTML/body storage.

Workers use row-lock SKIP LOCKED leases and random fencing tokens. Authority and suppression are checked under tenant-first locks before bounded transport. Lease exceeds transport timeout. Crash retries reuse stable provider idempotency and identical ciphertext/template. No retry after custody expiry; exhausted attempts become failed. Unavoidable uncertain provider acceptance uses at-least-once semantics, bounded well within Resend 24-hour idempotency. Provider accepted is distinct from delivered; neither proves reading, redemption or ownership. Provider events may precede acceptance persistence: unknown IDs are retryable, never silently dropped.

Recovery rehearsal changes an existing Better Auth credential hash and deletes that subject's customer_auth sessions in the same challenge-consumption transaction. It cannot create accounts or authorization rows. Production recovery stays disabled pending exact-provider/session/cache and lost-mailbox review.

0017 permits 0016 and 0017 review schemas without rewriting prior records. Keep versioned 0016 manifest; append 0017 and compute new schema identity/context digest. Old context/evidence remains historical and cannot qualify new release. Future migrations repeat this append-only strategy.
